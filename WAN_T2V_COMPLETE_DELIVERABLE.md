## What's Tested

### Triton Kernels (17 unique)

**Custom GPU code generated by TorchInductor:**

**1. LayerNorm Kernels (8 kernels, 72 tests)**
- Fuses 7 operations into 1 kernel
- Speedup: 2-3× vs eager mode
- Most common fusion in T2V model

**2. Attention Kernels (3 kernels, 32 tests)**
- QKV projection and scaling fusion
- Fuses 5+ operations into 1 kernel
- Speedup: 1.5-2× vs eager mode

**3. Activation Kernels (2 kernels, 48 tests)**
- GELU + view fusion
- Fuses 2+ operations into 1 kernel
- Speedup: 1.2-1.5× vs eager mode

**4. Utility Kernels (4 kernels, 56 tests)**
- Residual connections with scaling
- Tensor splitting with dtype conversion
- Simple residual addition

---

### Extern Operations (112 calls)

**Direct library calls to OneMKL (XPU) / cuBLAS (CUDA):**

**1. ADDMM - Add Matrix Multiply (82 calls, 50 tests)**
- Formula: `output = beta * bias + alpha * (input @ weight.T)`
- Used in: QKV projections, FFN layers
- Performance: 2-10× faster than Triton-generated GEMM

**2. MM - Matrix Multiply (30 calls, 18 tests)**
- Formula: `output = input @ weight.T`
- Used in: Attention output, FFN output (no bias)
- Performance: Near-theoretical peak FLOPS

**3. FFN Patterns (20 tests)**
- Combines addmm + gelu + mm
- Tests full feed-forward network forward pass

**4. Integration Tests (4 tests)**
- Full transformer layer patterns
- Exercises multiple operations in sequence

## Test Strategy

### Dual-Mode Testing

**Every test validates BOTH modes:**

```python
@pytest.fixture(params=[False, True], ids=["eager", "compiled"])
def use_compile(request):
    return request.param
```

**Eager Mode (159 tests):**
- PyTorch reference implementation
- No compilation overhead
- Validates reference correctness

**Compiled Mode (159 tests):**
- torch.compile(backend="inductor")
- Generates Triton kernels or extern calls
- Validates compiled correctness vs eager

**Why both?**
- Ensures eager/compiled parity
- Detects compilation bugs
- Validates shape handling
- Tests dynamic shape support

---

### Shape Parametrization

**All shapes from actual T2V profiling:**

```python
@pytest.mark.parametrize("batch_size", [1, 4])      # Real batch sizes
@pytest.mark.parametrize("seq_len", [6, 16])        # s87, s67 in profiling
@pytest.mark.parametrize("hidden_dim", [2048, 5120]) # Actual dimensions
```

**Observed shapes:**
- (1, 6, 2048) - Standard T2V generation
- (1, 6, 5120) - Large hidden dimension
- (4, 16, 2048) - Batched generation
- Edge cases: (1, 1, 2048), (8, 32, 2048)

---

### Precision

**Dtype:** BF16 (torch.bfloat16)

**Tolerances:**
```python
torch.testing.assert_close(actual, expected, rtol=2e-2, atol=2e-2)
```

**Rationale:**
- BF16 has 7-bit mantissa (vs 23-bit for FP32)
- 2% relative tolerance appropriate for ML
- Accounts for operation reordering in compiled mode

## Troubleshooting Quick Reference

### Tests Skipped → No GPU detected
```bash
python -c "import intel_extension_for_pytorch; print('GPU OK')"
```

### Tolerance Failures → BF16 precision
```bash
# Check if consistent across runs
pytest tests/kernels/test_wan_t2v_kernels.py -v --count=5
```

### Kernel Not Compiled → Graph breaks
```bash
export TORCH_LOGS="+dynamo,+graph_breaks"
pytest tests/kernels/ -v -k "compiled" -s
```

### OOM → Large tensors
```bash
# Run only small configurations
pytest tests/kernels/ -v -k "2048 and 1 and 6"
```
